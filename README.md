## 📝 Описание проекта

**pgXrayServer** — это комплексное решение для развертывания VPN-инфраструктуры на базе Ubuntu. Скрипт автоматизирует все этапы установки и настройки, от очистки системы до финальной конфигурации сервисов.

Проект поддерживает два основных сценария использования:
- **VPN-роутер** — для создания шлюза, раздающего VPN-соединение другим устройствам
- **VPN-клиент** — для простой настройки VPN на виртуальной машине или сервере

## ✨ Возможности

### Основные функции
- ✅ Полная автоматизация установки и настройки
- ✅ Поддержка протокола VLESS Reality
- ✅ Интерактивное меню с пошаговыми подсказками
- ✅ Интеллектуальная маршрутизация трафика
- ✅ Русскоязычный интерфейс

### Режимы работы

1. **Удаление и установка** — полная настройка VPN-роутера
2. **Обновление конфигурации Xray** — перенастройка VPN без переустановки
3. **Только удаление** — очистка системы от настроек
4. **Отключение GUI** — перевод Ubuntu в консольный режим
5. **Включение GUI** — возврат графической оболочки
6. **Настройка SSH** — конфигурация удаленного доступа
7. **Упрощенная установка для VM** ⭐ — быстрая настройка VPN-клиента (новое!)
8. **Выход** — завершение работы

### Маршрутизация трафика

Скрипт автоматически настраивает умную маршрутизацию:

- 🇷🇺 **Напрямую (без VPN):**
  - Российские домены (.ru, .su, .рф, .москва)
  - Государственные сайты РФ
  - VK, Yandex, Steam
  - BitTorrent трафик
  - Специфичные IP и порты

- 🌐 **Через VPN:**
  - Весь остальной трафик

- 🚫 **Блокировка:**
  - Windows NetBIOS порты (135, 137-139)
  - appcenter.ms

## 🖥️ Системные требования

- **ОС:** Ubuntu Server/Desktop (20.04, 22.04, 24.04)
- **Права:** root/sudo доступ
- **Интернет:** активное подключение для загрузки пакетов
- **Память:** минимум 512 MB RAM
- **Диск:** минимум 1 GB свободного места

### Для режима VPN-роутера дополнительно:
- Минимум 2 сетевых интерфейса (WAN + LAN)

### Для режима VPN-клиента (VM):
- 1 сетевой интерфейс с доступом в интернет

## 🚀 Установка

### 1. Настройка SSH доступа к GitHub

#### Генерация SSH ключа

```bash
# Генерируем новый SSH ключ (замените email на свой)
ssh-keygen -t ed25519 -C "your_email@example.com"

# Или для старых систем используйте RSA:
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

# Нажмите Enter для сохранения в стандартное место (~/.ssh/id_ed25519)
# Можно установить passphrase или оставить пустым
```

#### Добавление ключа в SSH-агент

```bash
# Запускаем SSH-агент и добавляем ключ (все в одной команде)
eval "$(ssh-agent -s)" && ssh-add ~/.ssh/id_ed25519
```

**Если возникает ошибка "Could not open a connection to your authentication agent":**

```bash
# Сначала запустите агент
eval "$(ssh-agent -s)"

# Затем добавьте ключ
ssh-add ~/.ssh/id_ed25519
```

> **Примечание:** SSH-агент нужен только для удобства. Git будет работать и без него, используя ключ напрямую из `~/.ssh/`.

#### Копирование публичного ключа

```bash
# Выводим содержимое публичного ключа
cat ~/.ssh/id_ed25519.pub
```

Скопируйте вывод команды (начинается с `ssh-ed25519 ...`)

#### Добавление ключа в GitHub

1. Откройте в браузере: https://github.com/settings/keys
2. Нажмите зеленую кнопку **"New SSH key"** (справа вверху)
3. Заполните форму:
   - **Title:** `Ubuntu Server` (или любое понятное название)
   - **Key type:** `Authentication Key` (оставьте по умолчанию)
   - **Key:** вставьте скопированный публичный ключ (всю строку!)
4. Нажмите **"Add SSH key"**
5. Подтвердите действие паролем GitHub (если попросит)

> ⚠️ **Важно:** Убедитесь, что скопировали **весь** ключ, включая `ssh-ed25519` в начале и email в конце!

#### Проверка подключения

```bash
# Проверяем соединение с GitHub
ssh -T git@github.com
```

**Ожидаемый результат (успех):**
```
Hi username! You've successfully authenticated, but GitHub does not provide shell access.
```

**Если видите ошибку "Permission denied (publickey)":**
- Ключ не добавлен в GitHub → вернитесь к предыдущему шагу
- Проверьте, что скопировали весь ключ: `cat ~/.ssh/id_ed25519.pub`
- Убедитесь, что используете правильный аккаунт GitHub

### 2. Клонирование репозитория

```bash
# Переходим в директорию для проектов
cd ~

# Клонируем репозиторий через SSH
git clone git@github.com:YOUR_USERNAME/pgXrayServer.git

# Переходим в директорию проекта
cd pgXrayServer

# Даем права на выполнение скрипту
chmod +x setup_final_bash.sh
```

> **Замените** `YOUR_USERNAME` на ваше имя пользователя GitHub

### 3. Подготовка VLESS-ссылки

Вам понадобится VLESS-ссылка от вашего VPN-провайдера.

#### Вариант А: Создать файл с ссылкой

```bash
# Создаем файл vless_link.txt
nano vless_link.txt
```

Вставьте вашу VLESS-ссылку (формат: `vless://...`), сохраните и закройте (Ctrl+X, Y, Enter)

#### Вариант Б: Ввести при запуске

Скрипт сам предложит ввести VLESS-ссылку, если файл не найден.

## 📖 Использование

### Запуск скрипта

```bash
# ВАЖНО: Запускаем с правами root
sudo bash setup_final_bash.sh
```

### Для VPN-роутера (полная установка)

1. Выберите пункт **1** в меню
2. Следуйте инструкциям на экране:
   - Настройте PPPoE (если требуется)
   - Выберите WAN интерфейс (интернет)
   - Выберите LAN интерфейс (локальная сеть)
   - Настройте DHCP сервер (опционально)
3. Дождитесь завершения установки
4. Подключите устройства к LAN порту

### Для VPN-клиента (упрощенная установка VM) ⭐

1. Выберите пункт **7** в меню
2. Укажите путь к файлу с VLESS-ссылкой или введите её вручную
3. Решите, нужна ли очистка предыдущих установок
4. Дождитесь завершения установки (2-3 минуты)
5. VPN автоматически активируется!

### Обновление VLESS-ссылки

```bash
# Запускаем скрипт
sudo bash setup_final_bash.sh

# Выбираем пункт 2 "Обновление конфигурации Xray"
```

### Проверка работы

```bash
# Проверить статус Xray
systemctl status xray

# Посмотреть логи
journalctl -u xray -f

# Проверить внешний IP (должен измениться при VPN)
curl ifconfig.me

# Проверить правила iptables
sudo iptables -t nat -L -n -v
```

## 🏗️ Архитектура проекта

### Структура файлов

```
pgXrayServer/
├── setup_final_bash.sh    # Основной скрипт установки
├── README.md              # Документация (этот файл)
├── CLAUDE.md             # Техническая документация для AI
└── vless_link.txt        # VLESS-ссылка (создается пользователем)
```

### Основные компоненты

#### 1. Xray Core
- **Протокол:** VLESS Reality
- **Inbounds:**
  - Transparent proxy (порт 12345)
  - DNS server (порт 53)
- **Outbounds:**
  - vless-reality (VPN)
  - direct (прямое соединение)
  - block (блокировка)
  - dns-out (DNS)

#### 2. Сетевая конфигурация
- **Для роутера:**
  - LAN IP: 192.168.100.1/24 (по умолчанию)
  - DHCP диапазон: 192.168.100.100-200
  - NAT masquerading

- **Для VM:**
  - Локальное прослушивание (127.0.0.1)
  - OUTPUT chain iptables
  - Исключение локальных сетей

#### 3. iptables правила

**Режим роутера:**
```bash
# Перехват DNS и трафика из LAN
PREROUTING -i LAN -p tcp/udp --dport 53 → REDIRECT --to-port 53
PREROUTING -i LAN -p tcp/udp → REDIRECT --to-port 12345
POSTROUTING -o WAN → MASQUERADE
```

**Режим VM:**
```bash
# Перехват исходящего трафика
OUTPUT -p tcp → XRAY chain → REDIRECT --to-port 12345
OUTPUT -p tcp/udp --dport 53 → REDIRECT --to-port 53
# Исключение: трафик пользователя xray (предотвращение петли)
```

### Конфигурационные файлы

После установки создаются/изменяются:
- `/usr/local/etc/xray/config.json` — конфигурация Xray
- `/etc/netplan/*.yaml` — сетевая конфигурация (только для роутера)
- `/etc/dhcp/dhcpd.conf` — DHCP сервер (опционально)
- `/etc/ssh/sshd_config` — SSH сервер (если настроен)
- `/etc/sysctl.conf` — параметры ядра

## 🔧 Устранение неполадок

### Xray не запускается

```bash
# Проверить логи
journalctl -u xray -n 50

# Проверить конфигурацию
/usr/local/bin/xray -test -config /usr/local/etc/xray/config.json

# Проверить VLESS-ссылку в файле
cat vless_link.txt
```

### VPN не работает

```bash
# Проверить правила iptables
sudo iptables -t nat -L -n -v

# Проверить маршрутизацию
ip route show

# Проверить DNS
nslookup google.com

# Для VM: убедиться что пользователь xray существует
id xray
```

### Нет интернета после установки (режим роутера)

```bash
# Проверить интерфейсы
ip a

# Проверить netplan
cat /etc/netplan/*.yaml

# Применить netplan заново
sudo netplan apply

# Проверить IP forwarding
cat /proc/sys/net/ipv4/ip_forward  # должно быть 1
```

### Очистка и переустановка

```bash
# Запустить скрипт
sudo bash setup_final_bash.sh

# Выбрать пункт 3 "Только удаление"
# Затем заново выбрать нужный режим установки
```

### GitHub SSH проблемы

#### Ошибка "Could not open a connection to your authentication agent"

```bash
# Решение: запустите SSH-агент
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# Или работайте без агента (ключ используется автоматически)
ssh -T git@github.com
```

#### Другие SSH проблемы

```bash
# Проверить SSH ключи
ls -la ~/.ssh/

# Проверить SSH агент
ssh-add -l

# Проверить разрешения (должны быть строгие)
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub

# Тестировать подключение с отладкой
ssh -vT git@github.com
```

#### Ошибка "Permission denied (publickey)"

Эта ошибка означает, что GitHub не знает ваш SSH ключ.

**Пошаговое решение:**

```bash
# 1. Проверьте, что ключ создан
ls -la ~/.ssh/id_ed25519*

# 2. Выведите публичный ключ
cat ~/.ssh/id_ed25519.pub
```

**Скопируйте вывод** (всю строку от `ssh-ed25519` до email)

**3. Добавьте ключ в GitHub:**
- Откройте: https://github.com/settings/keys
- Нажмите **"New SSH key"**
- Вставьте скопированный ключ
- Сохраните

**4. Проверьте подключение:**
```bash
ssh -T git@github.com
# Должны увидеть: Hi username! You've successfully authenticated...
```

**5. Если всё еще не работает:**
```bash
# Проверьте разрешения файлов
chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub

# Тест с отладкой
ssh -vT git@github.com
```
